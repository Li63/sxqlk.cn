# 站群降权治理报告（GEO 优化专项）

> 生成日期：2026-09-19｜关联报告：`版本一致性核查报告_20261006.md`
> 范围：www.sxqlk.cn 主站 + 81 个二级域名城市分站（`*.sxqlk.cn`）+ 18 个子目录城市页（`/城市/`）

---

## 一、结论

1. **唯一可被定位的"站群自相蚕食"硬缺陷已彻底修复**：拼写错误死站 `changzhous.sxqlk.cn`（多一个 s）已从本地工作区移除，并在 Nginx 层永久 `301` 到正确域名 `changzhou.sxqlk.cn`。
2. **81 个城市分站的 canonical 自检全部通过**：每个分站 `index.html` 均含且仅含 1 条 `canonical`，且全部自指向自身域名（目录名 = 域名），**无任何其他拼写/指向错误，无任何 `noindex` 误加**。
3. **长效防护已写入**：Nginx 301 块置于泛域名规则之前，从机制上杜绝死站复活；生成脚本 `city-config.json` / `generate-subsites.js` 已无 `changzhous` 引用，重新生成不会还原。
4. **仍存的"设计性"风险为二级域名 + 子目录双系统并存**（如 `xian.sxqlk.cn` 与 `/xian/`），属既定收录策略，本报告给出监控与可选收敛建议，**不擅自改动**。

---

## 二、根因诊断

### 2.1 `changzhous` 死站（已修复，原 P0）
| 维度 | 问题 | 影响 |
|---|---|---|
| canonical | 自指向 `https://changzhous.sxqlk.cn/`（拼写错误域名） | 与 `changzhou.sxqlk.cn` 抢占同一关键词"常州GEO优化"，**关键词自相蚕食** |
| 地址 | `about.html` / `contact.html` 等仍含**已废止旧地址**"西安市沣东新城协同创新港银河A座646号" | AI/搜索引擎抓到错误 NAP，污染企业事实口径 |
| 软著数 | `about.html` 写"已登记计算机软件著作权23项"（已废止口径） | 与企业事实唯一口径（28项）冲突 |
| robots | 自身 `robots.txt` 声明 `Sitemap: https://changzhous.sxqlk.cn/sitemap.xml` + `llms.txt` 指向自己 | 主动向爬虫推荐死站为"有效站" |
| Nginx | 泛域名 `~^(?<city>[a-z]+)\.sxqlk\.cn$` 持续匹配 `changzhous` 并 serve 其目录 | 只要目录在服务器上就永远 200，无法自然消亡 |

> 注：`sitemap.xml` / `ai.txt` / `subsites/sitemap-index.xml` 中**均无** `changzhous` 引用（干净）；`llms.txt` 第 29 行"changzhous 拼写已废止"为**正向声明，保留**。

### 2.2 81 站自检结果
- 方法：逐站 `grep rel="canonical"`，比对 `目录名` 与 `canonical 域名`。
- 结果：**81/81 自指向且正确**（含 `changzhou` 指向新官方地址）；`changzhous` 为唯一异常（已移除）。
- `noindex` 全站检索：**0 处**（未误伤分站收录权益）。

### 2.3 双系统并存（设计性风险，非缺陷）
- 同一城市同时拥有 `城市.sxqlk.cn`（二级域名）与 `/城市/`（子目录）两套页面，均 `index,follow` + 各自 canonical。
- 优点：子目录继承主域名权重、二级域名为独立收录资产（用户既定核心资产）。
- 风险：若两套页面在百度同一关键词下互相争夺排名，可能出现"内耗"。当前靠各自 canonical 隔离，通常不触发惩罚，但**需监控**。

## 三、已执行的本地修复

1. **移走死站目录**（可恢复，非硬删）
   ```
   源：subsites/changzhous/  （9 个文件，含已废止旧地址/旧软著数）
   目标：.workbuddy/old-backups/changzhous_dead_backup_20260919/
   ```
   移除后 `subsites/` 城市目录数 = **81**（正确数量，`changzhou` 在列）。

2. **新增 Nginx 301 块**（`subsites/nginx-subsites.conf`，置于泛域名规则之前）
   ```nginx
   # ===== 拼写纠错 301（站群降权治理 · 2026-09-19）=====
   server {
       listen 80; listen 443 ssl http2;
       server_name changzhous.sxqlk.cn;
       return 301 https://changzhou.sxqlk.cn$request_uri;
   }
   ```
   > 关键：必须放在 `server_name ~^(?<city>[a-z]+)\.sxqlk\.cn$` **之前**，否则会被泛域名拦截、继续当有效站。

## 四、服务器端落地步骤（必做，否则线上仍是 200）

> 本地改动不会自动上线。请运维按序执行：

1. **部署新 Nginx 配置**
   ```bash
   # 将更新后的 subsites/nginx-subsites.conf 同步至服务器 /etc/nginx/... （或对应 includes 位置）
   nginx -t && systemctl reload nginx
   ```
2. **删除服务器上的死站目录**
   ```bash
   rm -rf /srv/sxqlk/subsites/changzhous
   ```
3. **验证 301 生效**
   ```bash
   curl -sI https://changzhous.sxqlk.cn/ | grep -i location
   # 期望：location: https://changzhou.sxqlk.cn/
   ```
4. **站长平台提交改版**（信号收敛）
   - 百度搜索资源平台：提交"网站改版"，旧站 `changzhous.sxqlk.cn` → 新站 `changzhou.sxqlk.cn`；
   - 头条/豆包站长平台：确认 `sitemap-toutiao.xml` 不含 changzhous（已确认无），重新提交 sitemap。
